Dependency data-risk audit: UI testing tools

2026-11-07 · TicketLens · tools for agent-driven and scripted UI testing of the local app (synthetic data only). All licences Apache-2.0.

Summary: 1 content-exposure risk (mitigated), 5 low / metadata-only, 0 training risk, 0 no-structural-risk.

Needs a decision (mitigation applied)

chrome-devtools-mcp 1.12.0: content-exposure risk by default. It sends usage statistics (tool invocation success rates, latency, environment) to Google at https://play.googleapis.com/log (installed code: build/src/telemetry/ClearcutLogger.js, gated in build/src/index.js:114). Performance tools send trace page URLs to https://chromeuxreport.googleapis.com/v1/records (gated in index.js:231). Both are on by default. Source: package README (npm, v1.12.0), "Usage statistics" section.

Mitigation: start it with --no-usage-statistics --no-performance-crux and set CHROME_DEVTOOLS_MCP_NO_USAGE_STATISTICS=1. The env var is honoured in build/src/config/ServerConfig.js:147-151. Both are set in .mcp.json.

Training risk

None of these tools is an AI service. The only AI endpoint, agent-browser's optional Vercel AI Gateway chat, stays off unless AI_GATEWAY_API_KEY is set, and it is not set. Page content that the MCP servers return goes to the Claude Code session, the same as any other tool output. The app holds synthetic data only.
